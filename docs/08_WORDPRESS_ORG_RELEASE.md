# OxyArea FREE — WordPress.org Release Checklist

## Important commercial rule

WordPress.org guideline 5 prohibits trialware.

OxyArea FREE must not contain PRO functionality that is merely locked behind payment.

Preferred model:
- FREE code on WordPress.org;
- PRO is a separate add-on hosted/distributed outside WordPress.org.

## Submission requirements

Before submission:
- complete useful FREE plugin;
- GPL-compatible licensing;
- human-readable source/build instructions;
- valid `readme.txt`;
- correct plugin headers;
- translation-ready strings;
- Plugin Check passing;
- security review;
- no trademark issue;
- no undocumented external services;
- no unsolicited tracking.

## Name

Plugin Name:
`OxyArea – Private Client Area & User Portal`

Expected slug:
`oxyarea`

The final slug is assigned/confirmed through WordPress.org review.

## Upsell policy

Allowed approach:
- contextual links/cards on OxyArea's own admin screens;
- explain actual PRO features;
- sparse, dismissible notices if ever needed.

Avoid:
- dashboard hijacking;
- site-wide permanent nag;
- fake disabled controls everywhere;
- competitor keyword stuffing;
- affiliate spam.

## External services

FREE ideally has none.

If any service is added:
- disclose in readme;
- explain what data is sent and when;
- explicit user action/consent;
- privacy policy.

## Updates

FREE uses WordPress.org updates.

FREE must not install/download OxyArea PRO executable code from Oxysoft.

## Build/source

If JS/CSS is compiled:
- include source in distributed package or link clearly to maintained public source;
- document build steps.

## Submission milestone

Submit OxyArea FREE as soon as the following complete user flow works:

1. install;
2. create/select role;
3. configure login page;
4. build role dashboard;
5. protect a page by role;
6. configure role redirect;
7. log in as test user and see correct dashboard.

That is a complete FREE product, not a placeholder.
